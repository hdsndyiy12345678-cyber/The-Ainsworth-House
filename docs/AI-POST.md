# OpenAI 우편 연결 (배포 전 검토)

편지는 먼저 로컬에 봉인해 보관합니다. **AI 답장 요청 → 전송 내용 확인 → OpenAI에 전송**을 눌러야 서버로 보냅니다. 선택한 인물 설정과 이번 편지만 기본 전송하며, 이전 편지는 최대 5통까지 직접 선택합니다. 일기, 추리 정답, 이미지 첨부는 보내지 않습니다. 수신 편지는 `AI 창작 답장`으로 표시하고 원본 편지와 별도로 보관합니다. 이메일/실물 우편 서비스가 아닙니다.

## 로컬에서 실행

Node 24.22.1 이상을 사용합니다. 의존성을 설치한 뒤 서로 다른 터미널에서 실행합니다.

```sh
npm run dev:ai
npm run dev -- --port 5173
```

AI 서버는 `127.0.0.1:8788`에만 바인딩하고 Vite가 `/api/ai` 요청을 중계합니다. 공개 인터넷용 배포는 구현/실행하지 않았습니다. Netlify의 정적 `dist`만 업로드하면 이 Node 서버는 실행되지 않습니다. 향후 서버 호스팅·접근 제어·지속 저장소를 정한 뒤 연결해야 합니다.

서버 환경에 다음 두 값을 설정합니다. 로컬 개발에서는 Git에서 제외된 `.env.local`에 둘 수 있습니다. **실제 키를 채팅·커밋·HTML·VITE_ 변수에 넣지 마세요.**

- `AINSWORTH_AI_KEY`: OpenAI 프로젝트의 서버용 API 키. 일반 로컬 환경에서는 `OPENAI_API_KEY`도 읽지만, 이 관리형 클라우드에서는 예약 이름을 피한 `AINSWORTH_AI_KEY`를 사용합니다.
- `AINSWORTH_AI_ACCESS_CODE`: 서버 관리자가 생성한 별도 긴 연결 암호. OpenAI 키와 다른 값이어야 합니다. 앱의 **AI 우편 연결 → 연결 암호**에 입력합니다. 이 값은 프록시를 통해 외부로 전달하는 비밀이 아니라 서버에서 직접 비교할 로컬 비밀입니다. 클라우드 프록시 비밀 항목에 등록한 대체 토큰을 비교에 사용하지 마세요.

앱 서버와 같은 주소를 쓰면 AI 서버 주소는 비워 둡니다. 외부 서버를 연결할 때는 HTTPS 주소를 사용하고 서버의 허용 Origin을 정확히 지정해야 합니다. 브라우저 연결 암호는 sessionStorage에서 이 탭에만 유지하고 백업에 포함하지 않습니다. 서버 주소는 localStorage에 보관합니다. 키는 브라우저로 내려보내지 않습니다.

이 관리형 클라우드의 설정 초안에는 `AINSWORTH_AI_KEY` 비밀 요구 사항과 `api.openai.com` HTTPS 목적지만 추가했습니다. 실제 비밀 값은 없습니다. 환경 설정에서 키를 입력하고 저장한 뒤 **클라우드 환경을 게시**해야 적용됩니다. 이 작업은 Netlify 앱 배포와 별개이며 자동으로 실행하지 않았습니다. `npm run dev:ai`는 환경의 HTTPS 프록시와 신뢰 CA를 사용하는 Node의 `NODE_USE_ENV_PROXY=1`을 켭니다.

## 다운로드한 HTML에서 연결

그림·폰트·일기·연습은 인터넷 없이 작동합니다. AI 답장은 별도 실행 중인 서버가 필요합니다.

1. 같은 PC에서 AI 서버를 실행합니다.
2. HTML의 AI 우편 연결에서 `http://127.0.0.1:8788`과 연결 암호를 입력합니다.
3. 로컬 파일을 허용하려면 서버의 `AINSWORTH_AI_ORIGINS`에 `null`을 명시합니다. 예: `http://127.0.0.1:5173,http://localhost:5173,null`. 기본 설정에서는 파일 Origin을 허용하지 않습니다. 브라우저가 로컬 네트워크 권한을 요구하거나 파일 접근을 제한할 수도 있습니다.
4. 연결 확인 후 편지별 전송 내용을 확인합니다. 태블릿의 `127.0.0.1`은 PC가 아니라 태블릿 자신을 가리키므로, 다른 기기에서는 적절한 HTTPS 서버가 필요합니다.

## 비용과 복구

- 모델은 서버에 고정된 `gpt-4.1-mini`, 답장당 최대 900 출력 토큰, 입력은 최대 6통 × 통당 8,000자입니다.
- 기본 한도는 서버 전체 UTC 하루 20회입니다. `AINSWORTH_AI_DAILY_LIMIT`으로 1–100 범위에서 조정합니다. 금액 상한이 아닌 요청 횟수 제한이므로 OpenAI 프로젝트의 사용량·결제 한도도 관리해야 합니다.
- 서버는 호출 전 한도를 예약하고, 실패·시간 초과 요청도 한도에 포함합니다. 자동으로 새 유료 호출을 재시도하지 않습니다.
- 클라이언트는 전송 ID와 확인한 내용을 IndexedDB에 먼저 저장합니다. 네트워크가 끊기면 `전송 상태 다시 확인`이 같은 ID를 사용하므로, 서버가 이미 접수한 요청은 새로 생성하지 않습니다. 24시간이 지난 미확인 전송은 조회만 하고, 기록이 없으면 새 전송 내용을 다시 확인해야 합니다.
- 대기/작성/도착 상태는 앱 전체에서 갱신하며, 우편함을 닫거나 새로고침해도 이어집니다. 수신 결과는 한 번만 추가하고 읽기 전까지 새 편지로 표시합니다. 새 브라우저 세션에서는 연결 암호를 다시 입력하고 전송 상태를 확인해야 합니다.
- 서버 재시작 당시 호출 중이던 요청은 실패로 표시하며 자동 재호출하지 않습니다. 이미 요금이 발생했을 수 있다는 안내 후 새 전송 확인을 받습니다.
- 서버 기록은 Git에서 제외된 `.ainsworth-ai/queue.json`에 개인 권한(파일 0600/디렉터리 0700)으로 저장합니다. 완료 시 요청 본문은 제거하고 결과·ID·해시·사용량을 남깁니다. 완료/실패 기록은 24시간 후 다음 서버 접근 시 정리합니다. 앱에 수신한 편지는 계속 남습니다. 진행 중 작업은 완료/복구 전까지 유지합니다.
- 큐는 **단일 Node 프로세스**용입니다. 여러 프로세스/서버리스 인스턴스에서 같은 저장 파일을 공유하지 마세요. 운영 배포에는 원자적 예약·멱등성을 제공하는 지속 저장소가 필요합니다.
- 백업을 복원하면 진행 중 전송은 일시 정지하고 직접 상태를 확인하게 합니다. 연결된 서버 주소와 작업의 서버 주소가 다르면 연결 암호를 전송하지 않습니다.

## 검증

`npm run test:ai`는 실제 OpenAI 호출 없이 전송 형식, 선택 정보만 전송, 응답 오류·잘림, 인증·Origin, 요청 크기, 중복 방지, 지속 사용량, 재시작과 보관 기간을 검증합니다. Playwright는 편지별 동의·과거 편지 기본 제외·새로고침 후 수신·실패 후 같은 ID 재확인·받은 편지 중복 방지를 검증합니다. 실제 키가 없어 OpenAI 유료 호출은 검증하지 않았습니다.
