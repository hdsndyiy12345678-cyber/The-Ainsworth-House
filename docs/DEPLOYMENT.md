# 태블릿에서 사용하는 웹 배포

이 앱은 외부 서버/API 없이 동작하는 정적 웹앱입니다. 이번에 준비한 대상은 **사이트 루트에 배포하는 Netlify**입니다. ZIP은 준비된 결과물이며, 만들거나 다운로드하는 것만으로 인터넷에 게시되지 않습니다.

## 가장 간단한 방법: 완성된 폴더 업로드

1. `release/ainsworth-house-web.zip`을 다운로드합니다.
2. 압축을 풉니다. **`index.html`이 바로 들어 있는 폴더**를 찾습니다. `assets`, `sw.js`, `manifest.webmanifest`, 아이콘과 `_headers`도 함께 있어야 합니다.
3. PC 브라우저에서 [Netlify Drop](https://app.netlify.com/drop)을 열고 본인 계정으로 로그인합니다.
4. 압축 푼 폴더 전체를 업로드합니다. `index.html` 하나만 올리면 안 됩니다. **이 업로드 단계가 실제 공개 배포입니다.** 원하는 경우에만 진행하세요. 일반 GitHub 저장소 전체나 이 클라우드 환경 전체는 업로드하지 않습니다.
5. 완료 후 Netlify가 보여 주는 HTTPS 사이트 주소를 태블릿의 Chrome에서 엽니다. 주소는 배포 후 서비스에서 발급되므로 미리 정해져 있지 않습니다.
6. 첫 접속은 인터넷에 연결된 상태에서 화면이 완전히 표시될 때까지 기다립니다. Chrome 메뉴에서 제공되는 ‘홈 화면에 추가’ 또는 앱 설치 항목을 사용합니다. 설치 항목의 이름과 표시 여부는 기기에 따라 다릅니다. 설치하지 않아도 브라우저에서 사용할 수 있습니다.

폴더 업로드는 Windows PC에서 진행하는 편이 수월합니다. 태블릿에서 디렉터리 선택이 지원되지 않으면 PC에서 한 번 올린 다음 같은 HTTPS 주소만 태블릿에서 열면 됩니다. Netlify 계정·요금제와 업로드 UI는 서비스에서 확인하세요. 이 작업에서 계정 생성·유료 결제·외부 업로드는 실행하지 않았습니다.

## 이후 버전 업데이트

같은 Netlify 사이트의 수동 배포 기능에 새로 빌드한 폴더를 업로드합니다. 매번 새 사이트를 만들지 말고 기존 주소를 유지하세요. 업데이트 후 모든 앱 창을 닫았다 다시 열면 대기 중인 서비스 워커가 새 버전으로 전환됩니다. 기존 브라우저의 일기·편지는 배포 파일이 아니라 IndexedDB에 있으므로 그대로 유지됩니다. 업데이트 전 백업을 권장합니다.

## Git 연동으로 배포하고 싶은 경우

이번 변경에 `netlify.toml`도 포함했습니다. 앱 코드와 이 설정이 원격 저장소에 올라간 다음 Netlify에서 해당 저장소를 연결할 수 있습니다. 설정은 Node 24.22.1, 빌드 `npm run build`, 공개 폴더 `dist`입니다. 원격 푸시나 저장소 연결·배포는 이번 작업에서 실행하지 않습니다. 비공개 저장소도 계정에 부여된 접근 권한 범위에서 연결할 수 있습니다.

## 패키지 다시 만들기

Node.js와 Python 3가 설치된 환경에서:

```sh
npm ci
npm run package:web
```

이 명령은 타입 검사, Vite 빌드, 오프라인 서비스 워커 생성 후 배포용 ZIP을 만듭니다. ZIP 루트에 `index.html`이 들어가며, SHA-256 체크섬은 `release/ainsworth-house-web.sha256`에 기록합니다. `node_modules`, 소스 코드, Git 기록, 테스트 파일, 개인 JSON 백업은 포함하지 않습니다. `_headers`는 Netlify가 소비하는 설정 파일이라 서비스 워커의 사전 캐시 URL에서는 제외합니다.

앱은 현재 `/`를 기준으로 만들어졌습니다. GitHub Pages의 `/The-Ainsworth-House/` 같은 하위 경로에는 이 ZIP을 그대로 사용하지 마세요. 해당 호스팅을 사용하려면 Vite 경로·서비스 워커·매니페스트를 함께 수정해야 합니다. ZIP을 `file://`로 직접 여는 방식도 지원하지 않습니다.

## 기록과 주소

- 앱 자체의 정적 화면과 코드는 배포 주소에서 접근할 수 있습니다. 로그인으로 앱 진입을 제한하는 기능은 없습니다.
- 일기·편지·이미지·필기·펫 기록은 각 기기의 해당 HTTPS 주소에 속한 **IndexedDB**에 저장됩니다. 앱 코드는 기록을 Netlify나 다른 기기로 전송하지 않습니다. 호스팅 서비스에는 일반적인 접속 요청이 발생합니다.
- 클라우드 환경에서 작성한 기록은 태블릿에 자동으로 따라오지 않습니다. 기존 기기의 ‘설정과 백업 → JSON 백업 내보내기’ 후 태블릿의 같은 메뉴에서 가져오세요. 가져오기는 태블릿의 현재 기록을 확인 후 덮어씁니다.
- 사이트 이름·도메인을 바꾸면 브라우저는 다른 저장 공간으로 취급합니다. 이전 주소에서 백업하고 새 주소에서 복원해야 합니다. 주소를 바꾸거나 브라우저 데이터를 지우기 전에 백업하세요.
- 홈 화면 앱과 Chrome은 같은 주소·같은 브라우저 프로필을 사용해야 기록을 공유할 수 있습니다. 다른 브라우저·시크릿 모드에는 기록이 자동 공유되지 않습니다.

## 준비 단계의 검증과 이후 확인

로컬에서 프로덕션 빌드, ZIP 무결성과 파일 구성, 정적 자산 참조, 서비스 워커 캐시 목록을 검사합니다. 실제 Netlify 헤더 적용, 발급된 HTTPS 주소, 태블릿 설치와 S펜은 공개 배포 후 별도로 확인해야 하며, 로컬 통과를 원격 검증으로 표현하지 않습니다.
